## 1. 선언적 함수 (Function Declaration)
<callout color="gray_bg">
	- 가장 전통적인 방식으로. 이름을 붙여서 자신이 어떤 함수인지 선언하는 형태
	<br>- **문법** : `function 이름() { … }`
	- **특징** : 함수 자체가 코드의 맨 위로 올려지는 **호이스팅이 발생**합니다. <br>→ 즉, 함수를 만들기 전 줄에서도 호출이 가능
	```javascript
sayHello();

function sayHello() {
    console.log("안녕하세요!");
}
	```
</callout>
---
## 2. 익명 함수 (Anonymous Function)
<callout color="gray_bg">
	- 말 그대로 이름이 없는 함수로, 보통 변수에 대입하거나(함수 표현식), 다른 함수의 인수로 보낼 때 사용.
	<br>- **문법** : `const 변수명 = function() { … }`
	- **특징** : 변수에 할당하기 전에는 존재하지 않음. <br>→ **호이스팅이 발생하지 않거나**, 변수 선언 규칙(let, const)에 따라 **호출 순서가 엄격**함.
	```javascript
// sayHi(); // 에러 발생

const sayHi = function() {
    console.log("반가워요!");
};

sayHi();
	```
</callout>
---
## 3. 화살표 함수 (Arrow Function)
<callout color="gray_bg">
	- ES6에서 등장한 **익명 함수의 축약형**. 단순히 짧아진 게 아닌 this 바인딩이라는 기술 차이가 존재하며, **가독성**과 **간결함**이 핵심
	<br>- **문법** : `() ⇒ { … }`
	- **특징** : 익명 함수와 마찬가지로 변수에 담아 쓰며, **호이스팅 되지 않음**.
	```javascript
const add = (a, b) => a + b;
	```
</callout>

> **익명/화살표 함수를 쓰는 이유는 뭘까?**
	선언적 함수는 어디서든 쓸 수 있어 편하지만, 코드가 복잡해질수록 함수가 어디서 나왔는지 알기 힘들어지는 문제가 발생하는데, 익명/화살표 함수는 코드의 흐름을 강제하기에 어디서 만들었는지 알기 쉽다.
<callout color="gray_bg">
	⭐ **정리**
	- 미리 정의해두고 어디서든 편하게 쓰고 싶다? - **선언적 함수**
	- 특정 변수에 담아 깔끔하게 관리하고 싶다? - **익명 함수**
	- 코드를 짧게 줄이고 최신 스타일을 따르고 싶다? - **화살표 함수**
</callout>
